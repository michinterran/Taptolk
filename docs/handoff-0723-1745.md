## 7. 🔴 이번 세션에서 발견한 결함 (미수정)

**`renderSticker`가 특정 payload에서 자기 출력을 decode하지 못한다.**

`https://demo.taptolk.example/s/DEMO0000DLVR` 은 `ROUND_WHITE_MINIMAL_V1`·
`ROUND_BLUE_HOLOGRAM_V1` **양쪽에서** `QR_DECODE_MISMATCH`로 실패한다.
같은 템플릿의 다른 코드(`DEMO0000AAAA` 등)는 통과하므로 **템플릿이 아니라 payload 의존**이다.
결정론적으로 재현된다.

```bash
node -e "
(async()=>{const {readFileSync}=require('node:fs');
const m=await import('./packages/qr-engine/dist/render.js');
const logo='data:image/png;base64,'+readFileSync('design_concept/taptolk로고.png').toString('base64');
try{await m.renderSticker({publicUrl:'https://demo.taptolk.example/s/DEMO0000DLVR',taptolkLogoDataUri:logo,templateCode:'ROUND_WHITE_MINIMAL_V1'});console.log('OK')}
catch(e){console.log('FAIL',e.message)}})()"
```

**의미**: 실제 배치 생성에서도 일부 자산이 `QR_DECODE_MISMATCH`로 실패할 수 있다.
렌더 해상도(`density: 300`) 또는 QR 판 크기(460/540) 대비 module 밀도가 원인으로 보인다.
시드는 이 경우 샘플을 **만들지 않고 건너뛰며** 그 사실을 출력한다.
