## Frozen design decisions

- State path:

  ```text
  SAMPLE_APPROVED
  → FINAL_APPROVAL_PENDING
  → GENERATION_APPROVED
  → GENERATION_QUEUED
  ```

- The original Batch requester submits final approval and may cancel only before durable
  generation approval.
- Only an independent AAL2 Super Admin may write `GENERATION_APPROVED`.
- Final approval commits Batch state, redacted audit, and one
  `qr_generation_jobs.PENDING_DELIVERY` intent in the same PostgreSQL transaction.
- A bounded dispatcher publishes the stable `jobId` to Supabase Queues/pgmq.
- Queue delivery is at least once; business work is idempotent and does not claim exactly-once
  delivery.
- Provider delivery retries and generation execution attempts are counted separately.
- Default maximum generation execution attempts are five through typed/server configuration.
- Provider publish failure does not mark the Batch `FAILED`.
- Exhaustion before side effects becomes `FAILED`; committed partial work becomes
  `PARTIALLY_COMPLETED` and requires reviewed resume.
- Vercel Cron/Node Function may perform bounded dispatch/recovery only.
- QR generation/render consumption runs in a separately deployed Node 24 container. Exact host
  selection waits for benchmark evidence.
