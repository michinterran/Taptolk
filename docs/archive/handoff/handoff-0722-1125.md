## 5. 비협상 제약 (전 작업 공통)

- 공개 링크 보유는 권한이 아니다. 중앙 RBAC와 PostgreSQL RLS를 **모두** 통과해야 한다.
- `UI → Route Handler → Application Service → Domain Policy → Repository → PostgreSQL`
- 컴포넌트·Route Handler에 비즈니스 규칙·문구·URL·보존기간·rate limit 하드코딩 금지.
- **QR 수량 `1..100` per-Batch 유지.** 단일 1,000-item Batch 금지.
- **Production Cron 활성 정의 `0` 유지.** Vercel 요금제 변경 금지.
- canonical 단일 관리자 로그인, 고객/플랫폼 화면·권한 분리, MFA, redacted audit 유지.
- KO/EN typed dictionary parity, SemanticHeading, immutable logo(SHA-256 고정),
  EN "caller", QR enum·action label 유지.
- 전화번호·메시지·OTP·쿠키·인증 헤더·OAuth token·QR/activation/response token·
  Provider secret을 Git·문서·로그·테스트 출력·스크린샷에 남기지 않는다.
- 실제 전화번호·Production 데이터를 테스트에 쓰지 않는다.
- Production Supabase 프로젝트·리전·Secret, SMS/CAPTCHA/Enterprise SSO Provider,
  요금제, 모니터링·롤백·장애 대응 담당자를 임의로 선택하지 않는다.
- 기존 사용자 변경과 무관한 파일을 수정하지 않는다. 문서만 보고 완료로 판단하지 않는다.
