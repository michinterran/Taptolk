## 1. 화면 1장 "완료"의 정의

반복해서 화면을 다시 만든 원인은 완료 기준이 화면마다 달랐던 것이다. 7개를 모두
만족해야 그 화면은 끝난 것이고, Codex가 붙일 수 있는 상태다.

| | 항목 | 확인 방법 |
|---|---|---|
| 1 | **정본 근거** — 시안 파일과 위치. 시안이 없으면 §3 패턴 조합을 명시 | 커밋 메시지·주석 |
| 2 | **토큰** — 새 값은 `--tt-*`에. 화면 CSS에 수치 없음 | `validate:design-system` |
| 3 | **프리미티브** — `packages/ui`에서 조합 가능 | 화면이 마크업을 다시 쓰지 않음 |
| 4 | **KO/EN 카피 계약** — 타입 있는 카탈로그. 컴포넌트에 문구 없음 | `validate:wcj` C001·C002 |
| 5 | **상태 전부** — 빈·로딩·오류·권한없음·한도초과 | 아래 §2 |
| 6 | **데이터 계약** — `docs/design-canon/CONTRACTS.md`에 "서버가 줘야 하는 것" | 표에 행이 있음 |
| 7 | **눈으로 대조** — 같은 뷰포트에서 정본과 나란히 | 스크린샷 |

**6번이 이 분담의 핵심이다.** 디자인은 스키마를 기다리지 않는다. 서버가 아직 안 주는
값은 계약으로 선언하고 화면은 정직하게 비운다(`—`). 목업 숫자를 굽지 않는다
(`DESIGN_SYSTEM.md` §4).

## 2. 상태 커버리지 (운영자 확정 2026-07-24 — 전 상태 포함)

화면마다 해당되는 것을 전부 그린다. 나중에 몰아서 하지 않는다 — 상태를 뒤에 붙이면
레이아웃이 흔들리고, 그때 다시 정본과 대조해야 한다.

| 상태 | 규칙 |
|---|---|
| 빈 | 무엇이 생기면 채워지는지 말한다. 자리를 샘플로 채우지 않는다 |
| 로딩 | 레이아웃이 튀지 않는다 |
| 오류 | **복구 경로를 준다**(WCJ J004). 사유를 구분한다 |
| 권한 없음 | `0`이 아니라 `—`. 구역을 떼어내지 않고 잠금·읽기 전용 |
| 한도 초과 | 남은 시간·횟수를 말한다 |
| 알 수 없음 | **"못 물어봤다"를 "없다"로 표시하지 않는다** |
