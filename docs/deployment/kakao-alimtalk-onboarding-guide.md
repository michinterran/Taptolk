# 카카오 알림톡 연동 준비 가이드

> 작성: Claude · 2026-07-21
> 대상: 운영자(사용자)가 직접 수행하는 외부 절차
> 관련: `docs/development/workorder-kakao-alimtalk-live-provider.md` (Codex 구현 지시서)
>
> ⚠️ 카카오의 정책·심사 기준·화면은 수시로 바뀝니다. 아래 내용은 준비 방향이며,
> 실제 요건은 카카오 비즈니스 콘솔과 선정한 발송대행사에서 **최신 기준을 재확인**하세요.

---

## 1. 전체 흐름

앞 단계가 끝나야 다음 단계가 가능합니다. 병렬 진행이 안 되는 구조입니다.

```
1. 카카오 비즈니스 계정 생성
2. 카카오톡 채널 개설
3. 비즈니스 채널 인증          ← 사업자등록증 필요
4. 발송대행사(공식 딜러) 계약   ← 여기서 Taptolk 요구사항 확인 필수 (4절)
5. 발신프로필 등록             ← 채널을 딜러 콘솔에 연동, 카카오 승인
6. 템플릿 등록 및 검수 신청     ← ⏱ 가장 오래 걸리는 구간, 반려 가능
7. API 인증 정보 발급
8. 테스트 발송 검증
9. 운영 개시
```

**병목은 6번입니다.** 검수는 영업일 단위로 걸리고 반려되면 수정 후 재제출입니다.
그래서 **템플릿 문구를 미리 잘 준비하는 것이 전체 일정을 좌우합니다.**
5절에 초안을 준비해 두었습니다.

## 2. 준비물 체크리스트

### 2.1 지금 준비해야 할 것

- [ ] **사업자등록증** — 3단계 비즈니스 채널 인증에 필수. 없으면 여기서 완전히 막힙니다.
- [ ] **카카오 계정** — 개인 계정이 아닌 업무용 계정 권장. 담당자 변경 시 이관 문제를 피할 수 있습니다.
- [ ] **채널 이름과 프로필 이미지** — 차주가 알림톡을 받았을 때 보게 되는 발신자 정보입니다.
      낯선 이름이면 스팸으로 오인해 응답률이 떨어집니다. 서비스명과 일치시키세요.
- [ ] **도메인** — ✅ `taptolk.com` 확보 완료.
      템플릿에 링크를 넣으려면 채널에 등록·검증된 도메인이어야 하는 경우가 있습니다.
      딜러에게 **"템플릿 링크에 사용할 도메인 사전 등록이 필요한지"** 확인하세요.
- [ ] **예상 발송량** — 딜러 견적과 단가 협상에 필요합니다.
      단지 수 × 차량 수 × 월 예상 연락 건수로 개략치를 준비하세요.

### 2.2 나중에 필요한 것

- [ ] 테스트 수신용 번호 — 실제 발송 검증 시 사용. **본인 또는 동의받은 내부 인원 번호만** 사용하고,
      번호·메시지 원문을 문서·로그·채팅에 남기지 않습니다.
- [ ] 정산·비용 담당자

## 3. 알아두실 구조

- 알림톡은 **정보성 메시지**입니다. 광고·홍보 목적으로 쓸 수 없습니다.
  Taptolk의 차량 연락 알림은 정보성에 해당하므로 적합합니다.
- 수신자가 **카카오톡 사용자**여야 도달합니다. 미사용자에게는 발송이 실패합니다(4.2 참조).
- 발신 주체는 전화번호가 아니라 **카카오톡 채널**입니다.
- 대부분의 기업은 카카오와 직접 연동하지 않고 **발송대행사(공식 딜러)** 를 경유합니다.

## 4. ⚠️ 딜러 계약 전 반드시 확인할 것

여기가 이 문서에서 가장 중요한 부분입니다. Taptolk 코드가 이미 특정 방식으로
설계되어 있어서, 딜러가 이를 지원하지 않으면 **추가 개발이나 설계 변경이 필요**합니다.

### 4.1 기술 요구사항 (계약 전 확인)

| 확인 항목 | 왜 필요한가 | 미지원 시 영향 |
|---|---|---|
| **API 문서 공개 여부** | 어댑터 구현의 전제 | 문서 부실하면 개발 지연 |
| **멱등키(idempotency key) 지원** | 현재 재시도 로직이 중복 발송을 막는 구조 | 중복 발송 방지 로직을 별도 설계해야 함 |
| **발송 영수증(receipt) 조회 API** | 운영 KPI의 발송 성공률·비용 기록에 사용 | 비용 지표를 기록할 수 없음 |
| **실패 사유 코드 체계** | 재시도 가능/영구 실패 분류에 사용 | 무의미한 재시도로 비용 낭비 |
| **테스트/샌드박스 환경** | 실발송 없이 staging 검증 | 검증에 실제 발송 비용·리스크 발생 |
| **rate limit 정책** | 초과 시 fail-closed 처리 기준 | 예측 못 한 발송 실패 |

### 4.2 제품 결정 (딜러와 협의하며 정할 것)

**① 대체발송(SMS fallback) — 비활성 권장**

알림톡 실패 시 SMS로 자동 대체발송하는 옵션입니다. 딜러가 기본 활성으로 제안하는 경우가 많습니다.

**켜면 생기는 부담:**
- 차주 전화번호가 **SMS 사업자에게도 전달**됩니다 → 수탁자가 하나 늘고 개인정보처리방침에
  추가 기재해야 합니다
- **발신번호 사전등록** 의무가 새로 생깁니다
- 비용 구조가 이원화됩니다

**권장: 대체발송 미사용.** 계약 시 이 조건이 가능한지 확인하세요.
필요해지면 나중에 켤 수 있지만, 켠 채로 시작하면 개인정보 범위가 처음부터 넓어집니다.

**② 카카오톡 미사용자 처리**

수신자가 카카오톡을 쓰지 않으면 발송이 실패합니다. 대체발송을 끈다면 이 경우를 어떻게 할지
정해야 합니다.

- 실패로 처리하고 방문자에게 안내
- 관리사무소 에스컬레이션으로 전환 (기존 미응답 에스컬레이션 경로 재사용)

**권장: 에스컬레이션 전환.** 이미 구현된 경로가 있어 추가 개발이 적습니다.

**③ 영문 템플릿 등록 가능 여부**

Taptolk는 KO/EN을 지원하고, 알림 타입에도 `locale: "en" | "ko"`가 있습니다.
영문 템플릿 등록이 가능한지 딜러에게 확인하세요.

- 가능하면 KO/EN 둘 다 등록
- 불가능하면 **EN locale 요청을 어떻게 처리할지 결정**해야 합니다
  (한국어 템플릿으로 폴백 / 해당 locale은 발송 보류)

## 5. 정보성 템플릿 초안

> 아래는 Claude가 **Taptolk 코드가 실제로 보내는 변수**에 맞춰 작성한 초안입니다.
> 카카오 심사 기준에 맞춰 딜러와 함께 다듬은 뒤 제출하세요.
> **템플릿 ID는 승인 후 카카오가 부여합니다. 추측하거나 미리 정하지 마세요.**

### 5.1 시스템이 보내는 변수 (코드로 확정된 사실)

`packages/application/src/notification-reply-service.ts` 기준, 변수는 **정확히 2개**입니다.

| 변수 | 내용 |
|---|---|
| 요청 내용 | 연락 사유 (차량 이동, 이중주차, 라이트 켜짐 등) |
| 응답 링크 | 일회성 Taptolk 응답 URL (기본 1시간 후 만료) |

전화번호, 차량번호, 메시지 본문, QR 토큰은 **타입 수준에서 차단**되어 카카오로 전달되지
않습니다.

### 5.2 권장 구조 — 단일 템플릿 + 사유를 변수로

사유별로 템플릿을 따로 만들면 **검수를 사유 개수만큼 받아야 합니다.**
사유를 변수로 두면 템플릿 하나로 모든 사유를 처리할 수 있어 검수 부담이 크게 줄어듭니다.

### 5.3 한국어 초안

```
[Taptolk] 차량 연락 요청 안내

회원님 차량에 대한 연락 요청이 접수되었습니다.

▶ 요청 내용: #{요청내용}

아래 버튼을 눌러 응답해 주세요.
응답 링크는 일정 시간이 지나면 만료됩니다.

요청자에게 회원님의 전화번호는 공개되지 않습니다.
```

**버튼:** `응답하기` (웹링크) → `#{응답링크}`

### 5.4 영문 초안

```
[Taptolk] Vehicle contact request

A contact request was received for your vehicle.

▶ Request: #{requestReason}

Please use the button below to respond.
The response link expires after a limited time.

Your phone number is never shared with the requester.
```

**버튼:** `Respond` (웹링크) → `#{responseUrl}`

### 5.5 검수 통과를 위한 주의점

- **광고성 표현 금지** — 할인, 이벤트, 프로모션, 가입 유도, 마케팅 문구가 들어가면 반려됩니다.
- **변수만으로 구성 불가** — 고정 안내 문구가 반드시 있어야 합니다. 위 초안은 충족합니다.
- **수신자가 예측 가능한 내용** — 차주가 QR을 활성화하며 동의한 범위 안의 알림이므로 적합합니다.
- **링크 도메인** — `taptolk.com` 사전 등록이 필요한지 확인하세요.
- 발신자가 누구인지(`[Taptolk]`) 명확히 드러나야 오인 신고를 줄일 수 있습니다.

## 6. 절대 하지 말아야 할 것

- **알림톡을 본인확인 수단으로 쓰지 않습니다.**
  차주가 QR을 활성화할 때 쓰는 전화번호 본인확인 Provider는 **완전히 별개**이며,
  아직 선정되지 않았습니다. 알림톡은 "이미 확인된 차주에게 알림을 보내는" 수단일 뿐입니다.
- **발신프로필 키, API 인증 정보, 템플릿 ID를 Git·문서·채팅·스크린샷에 남기지 않습니다.**
  Claude나 Codex에게 값을 알려줄 필요가 없습니다. 운영자가 배포 환경의 시크릿 관리자에만
  직접 주입합니다.
- **실제 차주 전화번호로 테스트하지 않습니다.** 본인 또는 동의받은 내부 인원 번호만 사용합니다.

## 8. 개인정보처리방침 반영 (잊지 말 것)

카카오 계약이 확정되면 `docs/development/prd-public-surface-0721.md` Part C의
개인정보처리방침 **6항(위탁)** 을 갱신해야 합니다.

- 수탁자: 카카오 공식 딜러(발송대행사)명 + 카카오
- 위탁 업무: **"카카오 알림톡 발송"** (기존 초안의 "알림 문자 발송" 표현을 수정)
- 대체발송을 켠 경우 SMS 사업자도 수탁자로 추가

**처리방침이 갱신되기 전에는 Production 발송을 활성화하지 않습니다.**
