# Taptolk 모바일 정본

이 폴더가 차주·호출자 화면의 정본이다.

- **이미지 4장**은 승인된 시안이다. 그대로 만든다.
- **이 문서**는 시안이 없는 화면의 정본이다. Claude가 설계했고(2026-07-23, 운영자 지시),
  기존 4장의 시각 언어와 `Taptolk_User_Communication_and_Kakao_Risk_Report_2026.pdf`의
  제약을 따른다. **운영자 승인 전까지는 제안이다.**

---

## 0. 공통 (이미지 4장에서 읽은 것)

- 배경은 아주 옅은 회보라, 그 위에 흰 카드 스택
- 상단 taptolk 로고 (뒤로가기·타이틀바 없음)
- 선택지 = 아이콘 칩 + 한 줄. 강조 항목만 브랜드 틴트 + 브랜드 테두리
- **화면당 primary 버튼 1개.** 보내는 동작에는 로고 마크, 종료 확인에는 없다
- 하단 탭 `MESSAGES · ALERT · HISTORY · SETTINGS`, 활성 탭만 브랜드색
- **차량번호는 브랜드색 대형 수치**

### 구현 기준

**설치 없이 모바일 브라우저에서 먼저 동작한다.** 스캔이 설치된 PWA를 반드시 열지는
않으며(보고서 §02), 호출자는 무회원·무설치다. 설치하면 같은 화면이 PWA로 뜬다.

### 지어내지 않는다

시안에 "평균 응답 예상 시간 : 3분", "확인 평균시간 2분"이 있다. **실측이 쌓이기 전에는
그 줄을 그리지 않는다.** 목업 숫자를 그대로 굽는 것은 `DESIGN_SYSTEM.md` §4 위반이다.

## 1. 스캔 진입 — 서버가 분기한다

한 스티커, 한 URL이다. **무엇을 보여줄지는 서버가 자산 상태로 정한다.** 화면이 추측하지
않는다.

| 자산 상태 | 스캔한 사람 | 화면 |
|---|---|---|
| 미활성 | 누구든 | **[A] 활성화** — 스티커를 가진 사람이 차주다 |
| 활성 | 제3자 | **[B] 연락 요청** (이미지 4장) |
| 활성 | 차주 본인 | **[C] 내 스티커** — MESSAGES 탭 |
| 폐기·만료·정지 | 누구든 | **[E] 사용할 수 없는 스티커** |

차주 본인 판별은 이 기기에 남은 차주 세션으로 한다. 세션이 없으면 제3자 화면이다.

---

## 2. [A] 차주 활성화 — 3단계

**사이트는 고르는 것이 아니라 확인하는 것이다.** 스티커는 특정 사이트의 배치에서 나왔으므로
소속이 이미 정해져 있다. 차주가 사이트를 선택하게 하면 틀린 사이트를 고를 수 있다.

### A-1 · 시작

```
        taptolk
┌────────────────────────┐
│  [데모] 한빛마을 1단지     │  ← 사이트명, 굵게
│  아파트                  │  ← 사이트 유형, muted
│                        │
│  이 스티커를 등록하면      │
│  전화번호를 공개하지 않고   │
│  연락을 받을 수 있습니다.   │
└────────────────────────┘

  [🔷 등록 시작]              ← primary
```

- 사이트가 맞지 않으면 진행할 방법이 없다는 것을 여기서 알린다:
  `사이트가 다르면 관리사무소에 문의하세요` (텍스트 링크 아님, 안내문)

### A-2 · 차량번호

```
┌────────────────────────┐
│  차량번호를 입력하세요      │
│  ┌────────────────────┐│
│  │  12가 3456         ││  ← 대형 입력, 브랜드색 값
│  └────────────────────┘│
│  스티커를 붙인 차량의 번호   │
└────────────────────────┘

  [이전]        [🔷 다음]
```

- 형식 검증만 화면에서 한다. **중복·소유 판정은 서버가 한다**
- 이미 등록된 차량번호면 서버가 거부하고 사유를 돌려준다

### A-3 · 전화번호 인증

```
┌────────────────────────┐
│  연락받을 번호            │
│  ┌────────────────────┐│
│  │  010 0000 0000     ││
│  └────────────────────┘│
│  [인증번호 받기]          │  ← secondary
│  ┌────────────────────┐│
│  │  ● ● ● ● ● ●       ││  ← OTP, 발송 후에만 표시
│  └────────────────────┘│
│  남은 시간 2:58          │
└────────────────────────┘

  ✓ 번호는 암호화해 저장하고 호출자에게 보이지 않습니다

  [이전]        [🔷 인증하고 등록]
```

- **이 번호가 알림톡 수신 번호다.** 그 사실을 여기서 말한다
- 재발송은 쿨다운을 두고, 남은 시간을 표시한다
- 실패 사유는 구분해서 보여준다: 만료 / 불일치 / 시도 초과

### A-4 · 완료

```
┌────────────────────────┐
│      120라7098          │  ← 브랜드색 대형
│   등록이 끝났습니다.       │
│                        │
│  [데모] 한빛마을 1단지     │
│  알림톡으로 연락을 받습니다  │
└────────────────────────┘

  [🔷 시작하기]             ← MESSAGES 탭으로
```

### A 공통

- 스테퍼를 쓰지 않는다. 3단계뿐이고 각 화면이 한 가지만 묻는다
- 중간 이탈 후 다시 스캔하면 **마지막 완료 단계에서 이어진다**
- 활성화 토큰은 1회용·만료. URL에 차량번호·전화번호를 넣지 않는다(보고서 §13)

## 3. [C] 탭

### MESSAGES — 기본 탭

진행 중인 호출이 있으면 이미지 `03-owner-reply.png` 화면. 없으면:

```
┌────────────────────────┐
│  받은 연락이 없습니다      │
│  누군가 스티커를 스캔하면   │
│  알림톡으로 알려드립니다    │
└────────────────────────┘
```

동시에 여러 호출이 오면 카드를 쌓고 **오래된 것이 위**다. 먼저 온 사람이 먼저 기다렸다.

### ALERT — 알림 상태

```
┌────────────────────────┐
│  카카오 알림톡            │
│  010-0000-0000  [연결됨]│  ← 상태 배지
│                        │
│  채널을 차단하면 연락을     │
│  받을 수 없습니다.         │
└────────────────────────┘
┌────────────────────────┐
│  이 기기 알림  [켜기]      │  ← Web Push, 선택
└────────────────────────┘
```

- **알림톡이 기본 채널이다.** SMS는 알림톡을 쓸 수 없을 때의 대체이며,
  알림톡 기준으로 먼저 만든다(운영자 확정 2026-07-23)
- 전화번호는 **마스킹**해서 보여준다
- 채널 차단 상태를 서버가 알 수 있으면 표시하고, 모르면 **모른다고 둔다.**
  "연결됨"을 확인 없이 쓰지 않는다

### HISTORY — 지난 호출

```
2026.06.10 14:32   출차 요청        응답함  1분
2026.06.08 09:15   이동 요청        미응답   —
```

- 한 줄 = 시각 · 요청 유형 · 결과 · 응답까지 걸린 시간
- **결과가 없으면 `—`.** 미응답을 0분으로 쓰지 않는다
- 보고서 §13대로 메시지 본문은 만료되면 사라진다. 그때는 유형만 남는다

### SETTINGS

```
차량번호        120라7098          [변경]
연락처          010-****-0000     [변경]
관리 현장       [데모] 한빛마을 1단지
스티커 상태     사용 중
─────────────────────────────
스티커 사용 중지                    [중지]
등록 해지                          [해지]
```

- 사이트는 **읽기 전용**이다. 스티커가 소속을 정한다
- `중지`는 되돌릴 수 있고, `해지`는 바인딩을 끊는다. 둘을 같은 무게로 그리지 않는다 —
  `해지`만 danger
- 해지해도 **과거 호출 기록은 감사 목적으로 남는다.** 그 사실을 확인 화면에서 말한다

## 4. [E] 사용할 수 없는 스티커

폐기·만료·정지·알 수 없음을 **한 화면에서 사유만 바꿔** 보여준다.

```
┌────────────────────────┐
│  사용할 수 없는 스티커입니다 │
│                        │
│  <사유 한 줄>            │
└────────────────────────┘

  관리사무소에 문의해 주세요
```

- 어느 사이트의 스티커였는지 **말하지 않는다.** 폐기된 스티커로 사이트를 알아낼 수 있으면
  안 된다
- 재시도 버튼을 두지 않는다. 상태가 바뀌어야 풀린다

---

## 5. 세션 제약 (보고서 §09·§13 — 화면이 지켜야 한다)

- **무제한 채팅이 아니다.** 최초 요청 → 차주 답장 → 확인 → 추가 1~2회 → 완료
- 남은 왕복 횟수를 화면이 알려준다. 다 쓰면 입력을 닫고 이유를 말한다
- 응답 링크는 1회용·30~60분 만료. 만료되면 [E]와 같은 화면에 만료 사유를 쓴다
- 호출자 화면에 차주 전화번호를, 차주 화면에 호출자 전화번호를 **절대 그리지 않는다**

## 6. 미응답 에스컬레이션 (운영자 확정 2026-07-23)

차주가 일정 시간 응답하지 않으면 **호출자 화면에 관리사무소 연결 버튼**을 띄운다.
기다리는 쪽은 호출자이므로 이 버튼은 호출자 화면(`02-caller-sent-waiting`)에 붙는다.

### 시간 정책 — 보고서 §09의 권장값

| 경과 | 호출자 화면 | 서버 |
|---|---|---|
| 즉시 | 요청 접수·알림 발송 중 | 알림 큐 |
| 약 60초 | 아직 차주 확인 전 | 상태 재조회 |
| **약 180초** | **재호출 또는 관리사무소 알리기** | 중복 제한·에스컬레이션 허용 |
| 해결 | 해결 완료 | 세션 종료·임시정보 삭제 예약 |
| 만료 | 세션 만료 안내 | 응답 토큰·SSE 권한 폐기 |

**180초는 보고서의 권장값이지 제가 정한 값이 아니다.** 운영자가 바꿀 수 있어야 하므로
사이트 설정으로 두고, 컴포넌트에 하드코딩하지 않는다.

### 화면

180초 이후 `02-caller-sent-waiting`에 한 줄이 늘어난다:

```
        차주 메시지 확인 대기중
          경과 3분 12초

  [🔷 응답 새로 고침]           ← 여전히 primary

  [📞 관리사무소에 연락]         ← secondary, tel: 링크
     [데모] 한빛마을 1단지 관리사무소

     호출 내역 보기
```

- **전화번호를 화면에 인쇄하지 않는다.** 버튼이 `tel:`로 걸고, 라벨은 사무소 이름이다
- 사이트의 `escalation_phone_encrypted`를 **에스컬레이션 임계를 넘긴 세션에만** 서버가
  복호화해 내려준다. 그 전에는 응답에 담지 않는다
- 번호가 등록되지 않은 사이트면 **버튼을 그리지 않는다.** 눌러도 안 되는 버튼을 두지 않는다

### 관리사무소에 넘기는 정보 (보고서 §09)

차량번호 · 요청 유형 · 발송 성공/확인 상태 · 경과시간. **운영에 필요한 것만.**
호출자·차주의 전화번호는 넘기지 않는다.

### 상태를 정확히 구분한다

보고서가 못박은 것이고 화면이 지켜야 한다:

`보냈습니다` ≠ `차주가 확인했습니다`. 발송 요청 접수, 최종 발송 결과, 링크 열람, 실제 답장은
**서로 다른 사건**이다. 하나를 다른 하나로 표시하지 않는다.

### 재호출 제한

보고서는 `예: 3분 내 1회, 10분 내 총 2회`라고 **예시로** 적었다. 확정값이 아니므로
사이트 설정으로 두고, 기본값은 운영자 확정 전까지 정하지 않는다. (§8-L)

- **스티커 1장 = 차량 1대.** 한 계정에 여러 차량을 붙이지 않는다 (운영자 확정 2026-07-23)

## 8. 아직 정하지 않은 것

- **`멘트 더 보기`가 필요한지 자체가 미정.** 시안에는 있으나 3개로 충분할 수 있다.
  일단 3개 + 직접 입력으로 만들고, 링크는 목록이 생길 때 붙인다 (§8-M)
- **⚠️ 시안의 `★가장 많이 사용된 멘트` 라벨은 빈도 주장이다.** 실측이 없으면 그 라벨을
  달 수 없다. 데이터가 쌓이기 전에는 **첫 항목을 강조하되 별 라벨은 그리지 않는다** —
  `DESIGN_SYSTEM.md` §4
- **L** — 재호출 제한 기본값
- **M** — `멘트 더 보기` 도입 여부와 목록
