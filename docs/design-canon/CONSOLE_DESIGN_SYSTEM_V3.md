# Taptolk Console Design System v3

> 상태: reference-driven revision, 2026-08-20.
> 적용 범위: 슈퍼어드민, 관리회사 어드민, 사이트 어드민의 운영/관리 콘솔.
> 제외 범위: 랜딩, 로그인, 가입, 차주/호출자 PWA.

v3는 기존 v2 콘솔의 기능·데이터 계약을 유지하면서, 운영자가 첨부한 레퍼런스의 시각 언어와
작업 리듬으로 백오피스를 재정렬한다. 목표는 "검정 배경으로 칠한 관리자 화면"이 아니라,
운영자가 오늘 처리해야 할 일을 즉시 찾고 다음 행동을 확신할 수 있는 **운영실 cockpit**이다.

## 1. 시각 언어

- 배경은 거의 검정에 가까운 canvas다. 본문, 사이드바, 패널이 같은 검정 계열의 단계 차이로
  분리된다.
- 페이지 제목은 레퍼런스처럼 매우 크게 쓴다. 제목은 기능명 한 단어 또는 짧은 명사구로 두고,
  설명은 그 아래 한 줄로 제한한다.
- Taptolk 로고 원본은 바꾸지 않는다. 콘솔 액션 강조색은 레퍼런스의 hot pink/red 계열을
  운영 액션에 사용하고, QR/PWA의 공개 브랜드 보라색과 구분한다.
- 패널은 radius가 있는 1px hairline frame이다. 큰 그림자, 중첩 카드, 장식 배경은 사용하지
  않는다.
- 성공·주의·오류 상태는 숫자나 badge 옆에서 작게만 사용한다. 상태색으로 큰 패널을 칠하지 않는다.

## 2. 공통 셸

```text
┌──────────────────────┬───────────────────────────────────────────────┐
│ 운영실 sidebar        │ topbar: search / theme / locale / account     │
│ - role/scope card     ├───────────────────────────────────────────────┤
│ - 업무 단위 nav cards │ page header: connected / huge title / actions │
│ - session summary     │ status strip / queue / master-detail/table    │
└──────────────────────┴───────────────────────────────────────────────┘
```

- 사이드바는 넓은 업무 카드형 내비게이션이다. 좁은 아이콘 rail보다 각 메뉴의 의미와 상태가 먼저
  보여야 한다.
- 상단바는 보조 도구막대다. 전역 검색, 테마, 언어, 계정만 둔다.
- 본문은 왼쪽 정렬 작업 영역이다. 중앙 마케팅 column처럼 보이면 실패다.
- 화면 우측 floating refresh 같은 어정쩡한 액션은 금지한다. refresh/action은 페이지 헤더 action
  또는 탭바 action 영역에 정렬한다.

## 3. 정보 구조

### 대시보드

첫 화면은 메뉴 모음이 아니라 `운영 대기 모니터`다.

1. 오늘 처리할 대기 작업
2. QR 제작·입고·차주 등록 상태
3. 연락/응답 이상 징후
4. 관리회사·사이트 운영 건강도

### 관리회사 / 사이트

레퍼런스의 master-detail 패턴을 따른다.

- 좌측: 관리회사 또는 사이트 목록, 검색, 상태 필터
- 중앙: 선택된 항목 상세
- 우측 또는 하단: 승인·계약·QR·운영 이슈 queue

### QR 운영

QR 운영은 생성 화면이 아니라 lifecycle command center다.

1. QR 생성 요청
2. 제작·배송 확인
3. 입고·재고 확인
4. 차주 등록 현황
5. 예외·교체·폐기

차량번호 입력은 기본 여정이 아니다. 기본은 차주가 스티커를 받아 모바일에서 직접 등록한다.
관리자 차량 사전 배정과 CSV 일괄 배정은 운영 예외·대량 이전용 고급 기능으로 접어서 제공한다.

### 운영 모니터링 / 리포트 / 매출

- 운영 모니터링: 실시간 연락, 전송 실패, 미응답, escalation queue를 먼저 보여준다.
- 리포트: 기간, 사이트, 관리회사 필터와 요약 KPI, drill-down table을 한 프레임 안에 둔다.
- 매출/정산: 청구 가능, 결제 대기, 정산 보류, 환불/예외를 업무 상태별 queue로 묶는다.

## 4. 테이블과 목록

- 기본 페이지 크기는 20개다.
- 검색, 정렬, 상태 필터, 사이트/관리회사 필터는 표 바로 위 같은 frame 안에 둔다.
- 긴 목록은 row action을 반복 primary button으로 만들지 않는다.
- QR 식별 코드는 운영자가 찾는 보조 식별자다. 차주 이름·차량번호·상태·사이트가 함께 검색될
  수 있어야 한다.

## 5. 확인 dialog

- dialog는 viewport 중앙에 고정한다.
- overlay는 전체 화면을 덮고, dialog가 좌측 상단으로 붙는 상태는 실패다.
- 위험하거나 irreversible한 작업은 `무엇이 바뀌는지`, `대상`, `다음 상태`를 한 문장으로 보여준다.
- confirm button은 실제 form submit 또는 server action과 연결되어야 한다. 보이는 클릭만으로
  성공으로 보지 않는다.

## 6. 점진 전환 순서

1. 토큰과 공통 shell을 v3로 전환한다.
2. 대시보드를 운영 대기 cockpit으로 바꾼다.
3. QR 운영을 lifecycle 중심으로 재배치한다.
4. 관리회사/사이트를 master-detail workspace로 통합한다.
5. 운영·리포트·매출을 같은 frame/table 문법으로 정렬한다.
6. 라이트 모드는 같은 정보구조를 유지한 secondary skin으로 검증한다.
